See section 1 of `docs/phase-3/Phase3-Implementation-Notes.md`. In short: `npm install`, `npm run dev:db`, `npm run seed:admin`, `npm run seed:demo`, `npm run build`, `npm start`, then open http://localhost:5000.

## 4. Deviations from the submitted documents

Each item names the approved document, what the implementation does differently, and the reason.

| # | Document | Deviation | Reason |
|---|---|---|---|
| 1 | SDD 4.4.3, 8.2 (indexes) | `_id` is appended to the sort indexes and the API sorts by the same keys. | Stable, repeatable paging when several books share the same price or date. |
| 2 | SDD (libraries) | `bcryptjs` is used instead of the native `bcrypt` package. Same algorithm, cost factor 10 or higher. | Avoids native builds on student machines. VFR-04 is still met. |
| 3 | SDD (book data returned) | The public book shows `available` and `stockStatus`; `stock` and `reserved` are returned only to the owner and administrators. | Does not expose internal stock numbers to the public. |
| 4 | SRS FR-13, FR-14 | Payment and email use test adapters (a fake payment gateway and a console mailer). A real provider is not connected. | Provider and hosting were still TBD in Phase 2. The adapters implement the same interface a real provider needs. |
| 5 | SRS VFR-05, VFR-09, VFR-14 | HTTPS, hosting, the uptime monitor, the keep-alive and daily backups are not set up yet. | Planned in Sprint 2 (issue TASK-08). They cannot be shown on a local machine. |
| 6 | Phase 2 pseudo-code (payment) | A payment that arrives after the customer cancelled the unpaid order in another tab is not refunded automatically. | The same gap exists in the Phase 2 pseudo-code. It cannot happen with the test gateway in a normal run. Listed as a known limitation. |
| 7 | OpenAPI (API-31) | The payment session can only be rebuilt by restarting the payment from the page; `GET /api/orders/{id}` does not return it. | The approved contract has no field for it. The "Restart payment" button covers the case. |
| 8 | OpenAPI (webhook response) | The payment webhook answers `{ "received": true }`, which is what the SDD describes; the OpenAPI response schema says `message`. | The two Phase 2 documents disagree. The code follows the SDD. To be aligned in Sprint 2 (TASK-06). |

Known defects found while testing the finished product are tracked as Sprint 2 issues: restarting a checkout when the customer holds the last copies of a book (TASK-04), missing error states or retry buttons on a few screens (TASK-05), and tightening the browser security headers (TASK-07). Search response time at 100 users on one development machine was above the 500 ms target in our local measurements; it is to be re-measured on the deployed system (TASK-08).
